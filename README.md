# TaskFlow — To-Do List Web App with Firebase

**TaskFlow** is a modern, responsive, and accessible to-do list web application built with **plain HTML5, CSS3, and JavaScript (ES Modules)**, backed by **Google Cloud Firestore (Firebase)** for real-time cloud data persistence.

Developed for the **Teknika & Igire Rwanda Organization** Technical Assessment.

## ✨ Features

### 🌟 Core Requirements (100% Completed)
1. **Add Tasks:** Submit via button or `Enter` key. Whitespace-only or empty submissions are blocked with clear, accessible error messages. Maximum 100 characters enforced.
2. **Real-Time Display:** Tasks load sorted from newest to oldest. Uses real-time listeners so tasks sync instantly across multiple browser tabs and devices.
3. **Task Completion:** Mark tasks done with custom-styled checkboxes. Completed items display strikethrough text and persist status in Cloud Firestore.
4. **Edit Tasks:** Click the **Edit** button or double-click any task title to switch into inline editing mode. Supports `Enter` to save and `Esc` to cancel.
5. **Delete Tasks:** Secure deletion workflow with an accessible confirmation dialog before permanently removing documents from Firestore and the DOM.
6. **Filter Tasks:** Filter smoothly between **All**, **Active**, and **Completed** tasks with visual status highlighting.
7. **Active Task Counter:** Live counter indicating remaining tasks (e.g. `3 tasks left` or `1 task left`).
8. **Loading & Error States:** Dynamic loading spinner during fetch, and friendly error banners with retry triggers if network or Firestore issues occur.
9. **Responsive Design:** Mobile-first layout crafted with pure CSS Flexbox and media queries, verified for 360px mobile viewports up to wide desktop screens.
10. **Accessibility & Security (A11y & XSS):**
    - Semantic HTML5 (`header`, `main`, `form`, `ul`, `button`, `dialog`).
    - Visible and screen-reader accessible labels (`aria-label`, `aria-describedby`, `aria-live`).
    - Complete keyboard navigation and focus indicators.
    - Zero `innerHTML` injection for user input; uses `textContent` to prevent Cross-Site Scripting (XSS).

### 🎁 Stretch Goals & Bonus Features
- ⚡ **Real-Time Cross-Tab Sync:** Built using Firestore's `onSnapshot` listener instead of one-time `getDocs`.
- 🌓 **Dark Mode Toggle:** Smooth theme switching between Light and Dark mode using CSS custom properties (`var(...)`) and persisted via `localStorage`.
- 🧹 **Clear Completed:** Single-click batch deletion for all completed tasks using Firestore `writeBatch`.

## 🗄️ Firestore Data Model

Each task is stored as an individual document in the `tasks` collection:

| Field | Type | Example | Description |
|---|---|---|---|
| `id` | `string` | `aB3xK9...` | Unique document ID auto-generated by Firestore |
| `title` | `string` | `"Finish CSS layout"` | Task description (1–100 characters) |
| `completed` | `boolean` | `false` | Status flag, defaults to `false` |
| `createdAt` | `timestamp`| `serverTimestamp()` | Timestamp used to order tasks newest first |

## 🔒 Firestore Security Rules

Unlike default test-mode rules that expire in 30 days, TaskFlow includes production-grade security rules located in [`firestore.rules`](./firestore.rules) that validate data types and lengths:

```javascript
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /tasks/{taskId} {
      function isValidTask(data) {
        return data.keys().hasAll(['title', 'completed']) &&
               data.title is string &&
               data.title.size() > 0 &&
               data.title.size() <= 100 &&
               data.completed is bool;
      }

      allow read: if true;
      allow create: if isValidTask(request.resource.data) &&
                       request.resource.data.completed == false &&
                       request.resource.data.createdAt is timestamp;
      allow update: if isValidTask(request.resource.data);
      allow delete: if true;
    }
  }
}
```

## 🚀 Setup & Local Execution Guide

Because modern ES Modules (`type="module"`) are blocked when opening files directly with the `file://` protocol, you must serve the files using a local web server:

### Option 1: Using VS Code Live Server (Recommended)
1. Open the project folder in **Visual Studio Code**.
2. Install the **Live Server** extension (by Ritwick Dey).
3. Right-click `index.html` and choose **"Open with Live Server"**.

### Option 2: Using Node.js / npx
In your terminal, navigate to the project directory and run:
```bash
npx serve .
```
or
```bash
npx http-server -p 3000
```
Open your browser at `http://localhost:3000`.

## ⚙️ Connecting Your Own Firebase Project

1. Go to the [Firebase Console](https://console.firebase.google.com/) and click **Create a project**.
2. Give your project a name (e.g., `taskflow-assessment`) and finish creation.
3. In the project dashboard, click the **Web icon (`</>`)** to register a web app.
4. Copy the `firebaseConfig` object provided by Firebase.
5. In the left navigation, open **Build > Firestore Database** and click **Create database**. Choose your preferred region and start in **Test mode**.
6. Open [`firebase.js`](./firebase.js) in your code editor and replace the placeholder configuration with your keys:
   ```javascript
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "taskflow-assessment.firebaseapp.com",
     projectId: "taskflow-assessment",
     storageBucket: "taskflow-assessment.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abcdef"
   };
   ```
7. Go to the **Firestore Database > Rules** tab in the Firebase Console and paste the contents of [`firestore.rules`](./firestore.rules), then click **Publish**.
